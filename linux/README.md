# Сводка встречи — Linux

Первый целевой вариант: Ubuntu 24.04 и Debian 12/13, x86_64 с AVX2, PulseAudio либо PipeWire с `pipewire-pulse`. Сборка выполняется на Ubuntu 22.04, чтобы не требовать более новую glibc. Windows в этот выпуск не входит.

Приложение показывает прозрачное перемещаемое окно поверх других окон. Видимые кнопки и меню системного трея управляют записью, остановкой и источником: системный звук, микрофон, оба. На GNOME без поддержки трея кнопка «Скрыть» отключена. X11 — основной целевой сеанс: Wayland может ограничивать положение окна и режим поверх остальных окон; этот режим требует отдельной проверки на конкретном композиторе.

## Установка готового пакета

Установить `.deb` штатным установщиком пакетов либо `sudo apt install ./meeting-summary_0.7.0_amd64.deb`. Интерпретатор Python, Qt, CPU-движки и аудиоинструменты входят в пакет; вручную настраивать Python не требуется. Системный сервер звука должен работать.

AppImage содержит те же движки и аудиоинструменты. Разрешить выполнение файла, запустить его. Если FUSE отсутствует, поддерживается `APPIMAGE_EXTRACT_AND_RUN=1 ./MeetingSummary-0.7.0-x86_64.AppImage`. Графические библиотеки X11/OpenGL/EGL остаются системными.

При первом нажатии «Начать» автоматически загружаются закреплённые модели, всего около 6,84 ГБ. Требуется интернет и свободное место; загрузка показывает прогресс, прерванные файлы продолжаются. Каждый файл проверяется по размеру и SHA-256 из `meeting_summary/models.json`, ревизии моделей фиксированы. После загрузки распознавание и сводка выполняются локально без отправки записей и расшифровок. Модели хранятся в `$XDG_DATA_HOME/meeting-summary/models` либо `~/.local/share/meeting-summary/models`.

Модели по умолчанию: Parakeet TDT 0.6B v3 INT8 через sherpa-onnx и Qwen3.5-9B Q4_K_M через llama.cpp. Qwen сохраняет тот же размер и семейство, что macOS-версия; точность и скорость другого backend требуют отдельной оценки. Рекомендуется 16 ГБ оперативной памяти и не менее 10 ГБ свободного места. GPU не требуется. CPU может обрабатывать речь и сводку медленнее реального времени; отставание расшифровки показано в окне.

## Записи и сохранность

Полная запись и полный TXT создаются сразу в каталоге документов пользователя:

`Сводка встреч/YYYY-MM-DD/HH-mm-ss — Тема разговора — 8hexid.wav`

TXT имеет тот же stem. Сначала используется название «Встреча». После остановки приложение заканчивает распознавание оставшегося звука и пытается дать нейтральное название по началу, середине и концу встречи. Если название не прошло проверку, остаётся «Встреча». В TXT записан путь к аудио; JSON рядом содержит метаданные и состояние записи.

Аудио сохраняется до передачи в распознавание: PCM16, моно, 48 кГц; тишина сохраняется. Медленная сводка не останавливает запись и не сокращает полный TXT. Для сводки используется последнее пятиминутное окно; полная расшифровка остаётся отдельной. У записи WAV есть предел около 12 часов; приложение останавливает захват перед переполнением RIFF. При ошибке распознавания исходное аудио остаётся, интерфейс сообщает неполноту TXT.

Файлы и модели macOS не читаются и не изменяются. Linux-настройки лежат в собственном `QSettings('meeting-summary','linux')`.

## Сборка и проверка разработчиком

На Ubuntu 22.04 x86_64 установить системные зависимости из `.github/workflows/linux-build.yml`, создать отдельное окружение Python 3.12 и установить `linux/requirements-build.txt`. Затем выполнить `bash linux/build.sh`. Сборка выдаёт `.deb`, AppImage, SHA256SUMS и результаты проверки сохранённого приложения в `.build.noindex/linux`; временные каталоги удаляются на выходе. Модели в пакеты не входят.

Проверки без захвата и моделей:

```
python -m unittest discover -s tests -p 'test_*.py' -v
python -m unittest discover -s linux/tests -v
QT_QPA_PLATFORM=offscreen python linux/entrypoint.py --gui-smoke
```

Ручной запуск workflow `Linux packages and real CPU inference` с `inference=true` выполняет настоящие Parakeet/Qwen CPU inference только на уже разрешённом синтетическом `tests/meeting-sample.wav`, проверяет сохранение/повторное чтение полного WAV/TXT, реально захватывает виртуальные PulseAudio-источники по отдельности и вместе, проверяет GUI, собирает оба пакета, устанавливает `.deb` и запускает сохранённые артефакты. Отчёты и пакеты сохраняются в GitHub Actions artifacts на 14 дней. Запуск без этого флага не является проверкой качества реальной модели.

Локально на macOS проверены переносимые тесты и Qt API без аудиоустройств и моделей. Первый настоящий Ubuntu CI подтвердил программные проверки и отдельный системный/микрофонный захват, но совместный режим дал ноль PCM. Кандидат запрашивает у PulseAudio фрагменты по 50 мс вместо серверного значения по умолчанию; это исправление требует подтверждения следующим реальным прогоном. Тест сохраняет команду, stderr, время первого PCM и результат контрольного старого варианта до любых утверждений. Порог числа кадров и проверки двух тонов не ослаблены. GUI, модели и готовые пакеты должны подтверждаться отдельными отчётами workflow; наличие кода само по себе этого не доказывает.
